## Why this grid

Grid 2 falsified entry timing: the best config (dc20-4h-w, net PF 1.20) beat random entries
with the same exits in only 901/1000 seeds (`2026-10-04-base-grid2-fit.md`). The only lever that
moved numbers was exits: fewer, larger trades took dc20 from PF 0.83 to 1.20. Grid 3 tests
that lever routed by regime. The AI picks the machine's settings, never the trade.

- **H-router:** routing the trail on a regime label (wide when with-trend, tight otherwise)
  beats (a) random entries on the same with-trend bars with the same routed exits, and (b) the
  unrouted baseline. The label's timing must matter (shift null).
- **H-AI:** with c3's entries and the wide trail on for the same share of training bars, a
  local walk-forward classifier routes the trail better than the deterministic label.

Scope change (memo §4):
- **Venue:** perps → spot, long-only. Spot costs 0.10% + 0.05% per side, a 0.30% round trip
  (perps was 0.20%).
- **Hypothesis class:** entry timing → routing and exits.
- **Unchanged:** the window, symbols and data.
- **Ruling (Ada, 2026-10-05): fresh enough.** Regime-gated entries, routed exits and a fitted
  router are a different mechanism from grids 1/2, not a rehash.
- **1d fallback:** not triggered by data. The 15m spot history has one gap, 75 minutes on
  2023-03-24, before the window.

## Configs — dc20 Donchian entry, 4h, ATR(14) stop 3 / trail 5, spot long-only

| config | entry filter | trail, with-trend bar | trail, other bars | trail router | role (memo) |
|---|---|---|---|---|---|
| c1-base | none | 5 | 5 | — | C1: grid 2's best shape (dc20-4h-w) at spot costs; baseline only (D7) |
| c2-r1-gate | r1 = trend_up | 5 | 5 | — | C2: deterministic router, entries only |
| c3-r1-trail | r1 = trend_up | 5 | 3 | r1 | C3: + per-regime exits (D2) |
| c4-clf-trail | r1 = trend_up | 5 | 3 | clf | C4: c3 with the classifier routing the trail (D6) |

c4 vs c3 is the entire AI increment: the same entry rule, only the trail's labels differ. In
code, c4 is `router: r1` (entry filter) plus `exit_router: clf` (trail).

**Trail rule:**
- At each close of a held bar the trail uses 5 ATR if the config's trail router labels that
  bar with-trend, else 3 ATR. "Else" includes chop, trend_down and a missing or warmup label, so it fails closed.
- The chandelier only ratchets. A stop tightened on an off bar stays put when the label
  returns to with-trend.
- The stop stays 3 ATR in every config.
- 3 and 5 are grid 1/2's default and wide trails. No new multiple is introduced.

**Routers:**
- **r1:** `jev_regime.classify` (unchanged thresholds) one timeframe up from the supervisor's
  windows. It reads the last 60 × 1h + 120 × 4h bars closed by the signal close.
- **live:** the supervisor's 60 × 15m + 120 × 1h. No config uses it; it appears in the
  prescreen only, as the D1 evidence.
- **clf** (`jev_router`):
  - Model: L2 logistic (λ = 1 on standardized features, unpenalized intercept, Newton-IRLS),
    pooled over the 3 symbols.
  - Seven causal, scale-free features (CH-3): the r1 slope, vol ratio and width percentile;
    the live slope; 6- and 42-bar log momentum over ATR/close; the close's position in the
    20-bar range.
  - Label: the 4h close 6 bars (24 h) ahead is higher (see D6).
  - Walk-forward: one refit per calendar quarter (+07). Training rows run from 2022-01-01 and
    include only rows whose label window closes by the fold start (purged). That gives
    11 folds, 2024-01-01 .. 2026-07-01.
  - Exposure-matched threshold: τ switches on the same share of training rows as r1 has
    trend_up on them, so c4 vs c3 compares when the trail is wide, not how often.
  - Output: on = "trend_up", off = "chop", consumed exactly like a jev_regime label, by c4's
    trail only (D6).

Unchanged from grids 1 and 2:
- BTCUSDT/ETHUSDT/SOLUSDT, 2024-01-01 .. 2026-09-17 +07, end exclusive (the CLI refuses later).
- 15m Binance spot history resampled to 4h.
- Next-open fills and gap-aware resting stops.
- Halves split at 2025-05-10 by entry-signal time.
- Unit notional, not compounded.

No funding stress (spot). The CLI refuses `--book perps` for g3.

## Gate — a config is a forward-paper candidate only if ALL hold

1. n ≥ 100 trades (pooled).
2. Net PF > 1 overall AND in both halves.
3. sum% > 0 in a strict majority of symbols (≥ 2 of 3).
4. It beats its gated null in ≥ 99.75% of 1,000 seeds, i.e. **≥ 998/1000**. Beating means a
   strictly higher pooled sum%; ties count against (CH-4).
   - Bonferroni 0.05 / 20: 6 configs in grid 1 + 6 in grid 2 + 4 in the original-Jevelin
     pre-reg + 4 here.
   - Gated null: c1 → uncond; c2–c4 → matched (CH-1).
5. **(D3)** c2–c4 only: sum% > c1-base's sum% (`base`).

If nothing passes: the base strategy stays off forward paper, and there is no grid 4 on this
window (memo guardrail 3).

## Nulls — 1,000 seeds each, the same seed schedule in every arm

- **uncond.** Grid 2's control, with D5's exact rate:
  - Seeded coin-flip entries on flat bars at the strategy's exact rate (D5).
  - Long share 1 (spot).
  - Same exits; routed exits follow the same labels as the strategy.
- **matched** (CH-1): the same, but a drawn entry is dropped unless the config's entry router
  (r1 for c2–c4) labels its bar with-trend. The rate is re-weighted so the expected entry count
  matches the strategy. Exits follow the config's trail router, so c4's matched null differs
  from c3's only in the trail. It gates c2–c4. Without it, a router could win on its filter
  alone.
- **shift** (D4):
  - The strategy re-simulated with its own entry rule; the entry filter still reads the true
    labels.
  - Only the labels its trail reads (r1 for c3, clf for c4) are circularly rotated inside the
    window, by
    k ∈ [42, L − 42] bars (≥ 1 week either way), per symbol per seed. Entries can still
    differ slightly, because they need a flat book.
  - Same on-share and episode lengths, broken timing.
  - Reported for c3 and c4. It feeds the router claim, not the gate.

Reported per arm (CH-2):
- n at p5/p50/p95.
- Hold p50/p90 in bars.
- On-share of window bars and of held bars.

## Claims beyond the gate (printed by the harness, `_claims`)

- **Router claim** (c3, c4): gate PASS **and** beats its shift null ≥ 998/1000. A gate pass
  without the shift null is reported as "router timing not supported".
- **AI claim:** c4 gate PASS **and** c4 sum% > c3 sum%. Otherwise the report says the AI added
  nothing (memo guardrail 7), whatever the gate says.

## Deviations from the memo — rulings, 2026-10-05

- **D1. c2/c3 route on r1, not the live windows.**
  - Why: return-blind, from the prescreen; the live label's median episode is 1 bar on 4h.
  - Alternative: the memo literally, i.e. live windows. That would mostly test label noise.
  - **Ruling (Ada): approved.**
- **D2. The per-regime exit is a trail switch (5 / 3 ATR).** The memo had "chop: time-stop;
  stress: widened stop". Reasons:
  - jev_regime has no stress label (chop/trend_up/trend_down only).
  - A chop time-stop needs a new hold length that nothing pins. Choosing it would be a search
    on a spent window.
  - Both trail multiples are already-tested values.
  - **Ruling (Ada): approved.** A time-stop would be a new free parameter.
- **D3. New gate rule `base`:** c2–c4 must beat c1's sum%.
  - The memo said "unchanged mechanics". Without this rule, a routed config could pass on the
    matched null while doing worse than not routing.
  - It is guardrail 7's logic applied to the deterministic router.
  - **Ruling (Ada): approved.**
- **D4. New shift null** as the router-timing test. It is not gated; it is used only for the
  router claim. **Ruling (Ada): approved, informational only.**
- **D5. Exact control rate:** trades per eligible flat decision bar. This replaces grid 1/2's
  approximation. g1 and g2 keep the old rate and stay byte-identical. **Ruling (Ada):
  approved.**
- **D6. The clf target is the sign of the 24 h forward close; the clf routes the trail only.**
  - In form it is a regime label: on/off, exposure-matched, consumed like jev_regime.
  - The draft also made clf on c4's entry filter. Question: does that cross into the claim
    class grid 2 falsified?
  - **Ruling (Oracle): (b), exit router only.** A model trained on the forward-return sign
    deciding whether to enter is entry selection, which grid 2 falsified: dc20-4h-w beat random
    entries with the same exits in 901/1000 seeds against a 996 bar, and the one entry filter it
    tried (EMA) cut PF from 1.20 to 1.03 (`2026-10-04-base-grid2-fit.md`, Reading 2–3 and 5;
    grid 2 pre-reg `10bd1af`, amended `7b1bc74`). It also falls outside this grid's own scope
    change (entry timing → routing and exits) and the memo's "AI chooses the machine's
    settings, never the trade".
  - **Applied:** c4's entries are c3's r1 gate; clf labels reach only the trail
    (`exit_router`). The matched null draws on r1 bars for c4 as for c3, and the shift null
    rotates clf's labels. c4 vs c3 is one delta.
  - The target stays: it is fine as a router target. The alternative "r1 stays trend_up" would
    mostly relearn r1, which is c3.
  - Ada to confirm.
- **D7. c1 is conditioned.** Its shape is grid 2's best on this same window.
  - **Ruling (Ada): baseline only.** A c1 gate pass is reported, never promoted to forward
    paper; it would add nothing grid 2 has not shown. The report prints this rule.

Also declared:
- The classifier's training history starts 2022-01-01.
- The 2023-03-24 gap is 5 × 15m bars inside that history. It shortens one 1h and one 4h bar;
  there is no fill.

## Limits of the claim

- This is the same window as grids 1/2, already spent for entry timing. Only the venue and the
  hypothesis class change.
- A pass earns forward paper, which is the real out-of-sample test. It is not a claim of edge.
- The matched null prices 2024–26 drift and regime exposure; the shift null prices the label's
  base rate.
- c1 is conditioned on grid 2, so it is the baseline only (D7).
- The classifier is walk-forward and purged, so it is causal. It is not out-of-sample to the
  window as a whole: later folds train on earlier in-window bars.
